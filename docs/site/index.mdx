## Where a key goes

The same 32-byte key, held in an ordinary array and in a buffer from `Rent` with `isSensitive: true`, at three
moments of its life. [How secrets leak](/concepts/how-secrets-leak/#the-life-of-a-key) steps through all six.

Verify a signature with a key derived from a password. First the usual way, then with NCode.Buffers.

**With NCode.Buffers**


**What changed**

<PinNotes tone="fix">
1. The key is written into a pinned buffer and zeroed when `keyOwner` is disposed, on every exit.

## What it does. What it does not.

<CardGrid>
<Card title="It does">

- Allocate buffers for secrets on the pinned object heap. The collector does not move them, so no copy is left at an
  old address. <Proof claim="R3" />
- Overwrite the whole buffer with zeros in `Dispose`, including the part beyond the length you asked for.
  <Proof claim="R1" />
- Zero a pooled buffer before another caller can rent it. <Proof claim="R2" />
- Make you say whether a pooled buffer holds a secret: `isSensitive` has no default value.
  <Proof source="PublicApi.IsSensitive" />
- Compare spans of any unmanaged type in time that does not depend on their contents, for equal lengths.
  <Proof claim="R4" />
- Reject malformed UTF-8 and ASCII with an exception instead of substituting characters. <Proof claim="R5" />
- Refuse, at compile time, element types that hold references the zeroing would miss. <Proof claim="R8" />

</Card>
<Card title="It does not">

- Lock memory into RAM. The operating system can still write it to a page file, swap or a hibernation file.
  <Proof source="Roadmap.NotPlanned" />
- Hide memory from a debugger, a crash dump, or a process that can read this one's memory.
  [What it protects, and what it does not](/start/limits/)
- Zero anything you do not dispose. There is no finalizer. <Proof sample="SiteNoFinalizer" />
- Zero copies you make: a `string`, a `ToArray()` result, a buffer rented with `isSensitive: false`.
  <Proof sample="SiteCopiesAreNotCleared" />
- Clear a new buffer before you get it. Write before you read. <Proof source="SecureMemory.Allocate" />
- Hide the length of what it compares.
  <Proof test="CryptographicOperationsExtensionsTests.FixedTimeEquals_DifferentLengths_ReturnsFalse" />

</Card>
</CardGrid>

If an attacker can read your process's memory while a secret is in use, no managed library changes that. This one
reduces how many copies of a secret exist and how long they last. [What it protects, and what it does
not](/start/limits/) draws the line in full, and [Guarantees and their tests](/evidence/guarantees/) lists each claim
with the tests behind it and what they do not show.

## Check it yourself

- **Tests.** Each claim under "It does" names the test, or the line of code, that makes it true.
  [Guarantees and their tests](/evidence/guarantees/)
- **Samples.** Every C# sample on this site that compiles is a test in the repository, the usual code included. A
  sample that stops compiling or passing fails the build. Code shown as not compiling is marked so, with the
  compiler's error. <Proof source="SiteSamplesDecision" />
- **Coverage.** The build fails under 98% line or branch coverage. <Proof source="CoverageMinimums" />
- **Analysis.** Warnings are errors. The library's own code cannot call a lenient text encoding or rent from a pool
  without saying whether the buffer holds a secret: an analyzer rejects both. <Proof source="WarningsAsErrors" />
  <Proof source="BannedEncoding" /> <Proof source="BannedBuffers" />
- **Releases.** A package is built in CI from a tagged commit and pushed to nuget.org through trusted publishing after
  a maintainer approves. `SECURITY.md` lists the checks you can run on a package you downloaded. <Proof claim="R7" />
- **Decisions.** The reasons behind the design are on record, one short file each, in
  [docs/decisions](https://github.com/NCodeGroup/Buffers/tree/main/docs/decisions).

## In the package

- One assembly. It has no runtime state beyond the memory pools it creates, starts no threads and performs no I/O.
  <Proof source="Architecture.Scope" />
- It depends on Nerdbank.Streams, whose `Sequence<T>` the pooled buffer writers return, and on JetBrains.Annotations.
  <Proof source="PackageDependencies" />
- The target frameworks are the ones the package's project file declares. The badge above shows them,
  [nuget.org](https://www.nuget.org/packages/NCode.Buffers#supportedframeworks-body-tab) lists them, and the
  [changelog](https://github.com/NCodeGroup/Buffers/blob/main/CHANGELOG.md) records when one is added or dropped.
- Also in the package:
  - [Fixed-size buffer writers](/start/which-buffer/#a-fixed-span-writer) that throw instead of writing past the
    end. <Proof claim="R6" />
  - [Helpers that read a multi-segment buffer as one span](/guides/secret-of-unknown-length/), and copy only
    when they must.
  - [String splitting](/start/which-buffer/#helpers-you-will-meet) that slices the original instead of copying
    substrings.
  - [UTF-8 and ASCII encodings](/evidence/guarantees/#strict-encoding) that reject invalid input.
    <Proof claim="R5" />
  - [`ZeroMemory` and `FixedTimeEquals`](/start/which-buffer/#helpers-you-will-meet) for spans of any unmanaged type.
