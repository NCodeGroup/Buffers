This page holds one secret the way the library means it to be held. You install the package, watch a key turn to
zeros on your screen, then read a complete method that derives a key, checks a signature with it and leaves neither
the key nor the expected MAC behind. Every sample that runs on this page is a test in the repository, and the page
includes it from there.

## Install

```sh
dotnet add package NCode.Buffers
```

The package targets the frameworks its project file declares. [nuget.org's Frameworks
tab](https://www.nuget.org/packages/NCode.Buffers#supportedframeworks-body-tab) lists them, and this badge reads them
from the project file:
[![Target framework](https://img.shields.io/badge/dynamic/xml?url=https%3A%2F%2Fraw.githubusercontent.com%2FNCodeGroup%2FBuffers%2Fmain%2Fsrc%2FNCode.Buffers%2FNCode.Buffers.csproj&query=%2F%2FTargetFramework%20%7C%20%2F%2FTargetFrameworks&label=target&logo=dotnet&color=512BD4)](https://www.nuget.org/packages/NCode.Buffers#supportedframeworks-body-tab)

It brings two dependencies: Nerdbank.Streams, whose `Sequence<T>` the pooled buffer writers return, and
JetBrains.Annotations. <Proof source="PackageDependencies" />

## Line by line

<PinNotes tone="fix">

1. `Rent` with `isSensitive: true` rents a buffer on the pinned heap, so the collector does not move the key.
   <Proof claim="R3" /> `key` is the 32 bytes you asked for, and `keyOwner` owns the whole buffer: disposing it
   overwrites all of it with zeros. <Proof claim="R1" /> The buffer is not cleared before you get it, so read only
   what you wrote. <Proof source="SecureMemory.Allocate" />
2. `Pbkdf2` writes the derived key straight into `key`. The overload that returns a new `byte[]` would leave the key
   in an ordinary array that nothing clears. <LeakCard leak="L2" />
3. `stackalloc` puts the expected MAC on the stack, and `GetSecureLifetime()` zeroes it when `expectedLifetime` is
   disposed. It pins nothing, and stack memory needs no pinning. <Proof source="BufferExtensions.GetSecureLifetime" />
4. `FixedTimeEquals` takes the same time wherever the two MACs differ, for MACs of the same length.
   <Proof claim="R4" />

</PinNotes>

`key` and `keyOwner.Memory` are two views of one buffer, and their lengths differ:

## What you got, and what you did not

<CardGrid>
<Card title="You got">

- A key the collector does not move, in a buffer that is zeroed when `keyOwner` is disposed. <Proof claim="R3" />
  <Proof claim="R1" />
- An expected MAC that is zeroed when `expectedLifetime` is disposed. <Proof claim="R1" />
- A comparison whose time does not depend on where the MACs differ. <Proof claim="R4" />

</Card>
<Card title="You did not get">

- Memory locked into RAM, or hidden from a debugger or a crash dump: [what it protects, and what it does
  not](/start/limits/).
- Zeroing without `Dispose`: there is no finalizer to do it later. <Proof sample="SiteNoFinalizer" />
- Zeroing of copies you make, such as a `ToArray()` result or a `string`. <Proof sample="SiteCopiesAreNotCleared" />

</Card>

## Three rules before you write more

1. **Always `using`.** It disposes on every way out of the block, an exception included; that is the language's rule.
   <Proof external="UsingStatementDocs" /> A `Dispose()` call written after the work never runs when the work
   throws. <LeakCard leak="L6" />
2. **Write the `out` type.** `Rent` has a `Span<T>` overload and a `Memory<T>` overload, so `out var` does not
   compile:

   ```cs title="Does not compile" wrap
   using var keyOwner = BufferFactory.Rent(32, isSensitive: true, out var key);
   // error CS0121: The call is ambiguous between the following methods or properties:
   // 'NCode.Buffers.BufferFactory.Rent(int, bool, out System.Span<byte>)' and
   // 'NCode.Buffers.BufferFactory.Rent(int, bool, out System.Memory<byte>)'
   ```

   Write `out Span<byte> key` in synchronous code, and `out Memory<byte> key` when the buffer must cross an `await`,
   as [Keep a secret across an await, or in a field](/guides/secrets-across-await/) shows.
3. **Do not copy the secret out.** `ToArray()`, `Convert.ToHexString` and a `string` each make ordinary memory that
   `Dispose` never reaches. <LeakCard leak="L9" />

To have the build hold you to them, see [Ban the leaky APIs at build time](/guides/ban-leaky-apis/).
