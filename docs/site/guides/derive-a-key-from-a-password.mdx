This is your situation when your code holds a password or a passphrase, derives a key from it with PBKDF2, and uses
the key. The example decrypts a document with a key derived from a passphrase.

You'll use `BufferFactory.Rent` · `Rfc2898DeriveBytes.Pbkdf2` · `AesGcm` · `CryptographicOperations.FixedTimeEquals`

## The usual code

It turns the password into bytes, derives the key into a new array, and decrypts.

<Pinned tone="usual">
```cs snippet=SitePasswordKeyUsual title="Documents.cs" "byte[] key = Rfc2898DeriveBytes.Pbkdf2(" "Encoding.UTF8.GetBytes(password)" "aes.Decrypt("
```
</Pinned>

**Leaves behind**

<PinNotes tone="usual">

1. The key, in an ordinary array. The collector can move it and leave a copy behind, and nothing clears either. <LeakCard leak="L1" /> <LeakCard leak="L2" />
2. The password again, as bytes in an array of its own that nothing clears. <LeakCard leak="L9" />
3. No cleanup on any path. When the tag does not match, `Decrypt` throws, so a `ZeroMemory` call written after it
   would never run. <Proof sample="SitePasswordKeyUsual" /> <LeakCard leak="L6" />

</PinNotes>

## With NCode.Buffers

The same decryption, with spans for parameters, the key in a rented sensitive buffer, and `using` on every way out.

<Pinned tone="fix">
```cs snippet=SitePasswordKeyDecrypt title="Documents.cs" "BufferFactory.Rent(" "Rfc2898DeriveBytes.Pbkdf2(" "aes.Decrypt("
```
</Pinned>

**What changed**

<PinNotes tone="fix">

1. The key is written into a buffer rented with `isSensitive: true`. It is pinned, so the collector does not move it,
   and it is overwritten with zeros when `keyOwner` is disposed. <Proof claim="R3" /> <Proof claim="R1" />
2. The password reaches `Pbkdf2` as characters, through the overload that takes a `ReadOnlySpan<char>` and writes
   into a span. Your code makes no byte array of the password, and puts the key only in the rented buffer. `AesGcm`
   keeps its own copy until it is disposed, at the end of the same scope.
3. `Decrypt` still throws when the tag does not match, and the two `using` declarations still dispose `aes` and
   `keyOwner` on the way out. <Proof external="UsingStatementDocs" /> <Proof sample="SitePasswordKeyDecrypt" />

</PinNotes>

Both versions derive the key the sender derived: each test decrypts a document encrypted with the same password, and
both throw on a tag that was changed.

## Pitfalls

[Ways to get it wrong](/reference/pitfalls/) has more, each with its evidence.

- **`out var key`.** *You write* `out var key` in the call to `Rent`. *What happens:* it does not compile, because
  the compiler cannot choose between the `out Span<T>` and `out Memory<T>` overloads.

  ```cs title="Does not compile" wrap
  using var keyOwner = BufferFactory.Rent(32, isSensitive: true, out var key);
  // error CS0121: The call is ambiguous between the following methods or properties:
  // 'NCode.Buffers.BufferFactory.Rent(int, bool, out System.Span<byte>)' and
  // 'NCode.Buffers.BufferFactory.Rent(int, bool, out System.Memory<byte>)'
  ```

  *Write instead:* `out Span<byte> key`. [It did not compile](/reference/pitfalls/#it-did-not-compile)

- **Using `keyOwner.Memory` as the key.** *You write* `keyOwner.Memory` where the key goes. *What happens:* you get
  the whole 4096-byte buffer behind `key`. <Proof test="SecureMemoryPoolTests.Rent_SizeLessThanPage_ReturnsPageSizeBuffer" />
  *Write instead:* `key`, exactly the length you asked for.
  <Proof test="BufferFactoryPropertyTests.Rent_WithSpan_ReturnsABufferOfTheExactRequestedLength" />
  [Using the whole rented buffer](/reference/pitfalls/#using-the-whole-rented-buffer)
- **Leaving the cipher object out of the scope.** *You write* an `AesGcm` without `using`. *What happens:* it keeps
  the key until it is disposed. *Write instead:* `using var aes`, in the key's scope.
  [An API object that keeps the key](/reference/pitfalls/#an-api-object-that-keeps-the-key)
- **Holding the key across an `await`.** *You write* an `await` while the key is a `Span<byte>`. *What happens:*
  CS4007, "cannot be preserved across 'await' or 'yield' boundary". *Write instead:* `out Memory<byte>`, as [Keep a
  secret across an await, or in a field](/guides/secrets-across-await/) shows.
- **Copying a password that arrived as a `string`.** *You write* `Encoding.UTF8.GetBytes(password)`. *What
  happens:* one more copy that nothing clears, beside a string nothing can erase. <LeakCard leak="L5" /> *Write
  instead:* pass it on as a `ReadOnlySpan<char>`, as the sample does.
  [A string of the secret](/reference/pitfalls/#a-string-of-the-secret)
- **Guarding the salt and the nonce.** *You write* the salt, the nonce or the iteration count into a sensitive buffer.
  *What happens:* nothing is gained: they are not secrets, and travel beside the ciphertext. *Write instead:* store
  and send them in the clear. Only the password and the key need a sensitive buffer.

## What this does not fix

:::caution[Outside this method]
- **The password string your framework made** before your code ran, and the request body it came in.
- **The plaintext you hand back.** `plaintext` is the caller's buffer, and the caller decides how it is held.
- **A reader of the process while the key is in use,** such as a debugger or a crash dump:
  [what it protects, and what it does not](/start/limits/).
- **A weak derivation.** The algorithm and the iteration count are yours to choose.
:::

## Checklist

- The derived key is in a buffer from `Rent(..., isSensitive: true, ...)`, or in stack memory under
  `GetSecureLifetime()`, never in a returned `byte[]`.
- The owner of that buffer is in a `using`.
- No `Encoding.UTF8.GetBytes(password)`.
- Algorithm objects that took the key, such as `AesGcm`, are disposed in the same scope.
- Nothing derived is logged, encoded as text or copied with `ToArray()`.
- A derived value is compared with `FixedTimeEquals`.
