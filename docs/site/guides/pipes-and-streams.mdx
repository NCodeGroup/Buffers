This is your situation when a secret passes through a `Pipe`, or a `PipeReader` reads it from a stream, such as a
request body that carries a token or a key. The pipe keeps the bytes in buffers it rents from a pool. The examples give
it a pool that zeroes them.

## The usual code

A pipe made without options. The writer copies the secret in, the reader reads it back.

## With NCode.Buffers

The same pipe, with a pool of your own. The pipe rents its buffers from it, and the pool zeroes each one when the pipe
returns it.

<Pinned tone="fix">
```cs snippet=SitePipelinesSecurePool title="Pipelines.cs" "new SecureMemoryPool<byte>()" "new PipeOptions(pool: pool)"
```
</Pinned>

**What changed**

<PinNotes tone="fix">

1. The pool is yours: your application creates it and disposes it, and the pipe never does. <Proof sample="SitePipelinesSecurePool" />
2. The pipe's buffers are pinned pages from `SecureMemoryPool<byte>`, and each is zeroed when the pipe returns it.
   <Proof claim="R1" /> <Proof sample="SitePipelinesSecurePool" />
   <Proof test="SecureMemoryPoolTests.CanBeUsedAsMemoryPool" /> The pipe asks for one 4096-byte buffer, and the
   pool is still usable after both ends complete. <Proof sample="SitePipelinesSecurePool" />

</PinNotes>

Complete both ends, as the sample does, so the pipe returns every buffer it still holds.

### One span from a pipe

A read can come back in more than one segment, and an API that wants one span, such as a MAC or a cipher, can't take a
sequence. `GetSpanLease` on the sequence returns its own span when it has one segment, and a copy in a rented buffer
when it has several.

<Pinned tone="fix">
```cs snippet=SitePipelinesSequenceLease title="OneSpan.cs" "GetSpanLease(isSensitive: true)"
```
</Pinned>

<PinNotes tone="fix">

1. The copy is made in a buffer from `Rent` with `isSensitive: true`, which is pinned and zeroed when the lease is
   disposed, so the span of a split read never sits in an ordinary array. <Proof sample="SitePipelinesSequenceLease" />
   <Proof test="SequenceExtensionsTests.ReadOnlySequenceGetSpanLease_MultipleSegments_CopiesIntoARentedBuffer" />

</PinNotes>

Dispose the lease before you call `AdvanceTo`, as the sample does, and use the span only inside it.

## Pitfalls

[Ways to get it wrong](/reference/pitfalls/) has more, each with its evidence.

- **A minimum segment size above 4096 bytes.** *You write* `new PipeOptions(pool: pool, minimumSegmentSize: 8192)`.
  *What happens:* the pool rents a buffer larger than a page as a pinned array of its own, which it does not keep for
  reuse. Every segment of the pipe is one of those.
  <Proof test="SecureMemoryPoolTests.Rent_LargeBuffer_IsNotPooled" /> *Write instead:* a minimum segment size of 4096
  bytes or less, so the pipe's buffers are the pool's pages.
- **Copying out of the pipe.** *You write* `result.Buffer.ToArray()`, as the samples do to check what was read.
  *What happens:* the pool covers the pipe's buffers only. The copy is an ordinary array that nothing zeroes.
  <LeakCard leak="L9" /> *Write instead:* read the sequence in place, or copy into a sensitive buffer, such as one
  from `BufferFactory.Rent` with `isSensitive: true`.
- **Bytes left in the pipe.** *You write* a read that does not consume what it read, or code that completes only one
  end. *What happens:* a buffer that holds bytes nobody consumed stays rented, and unzeroed, until both ends complete.
  <Proof sample="SitePipelinesUnconsumed" /> *Write instead:* consume what you read with `AdvanceTo`, and complete both
  ends on every path, such as in a `finally` block.

## What this does not fix

:::caution[Outside this guide]
- **Sockets, TLS and the web server.** They buffer with pools of their own, and a pipe you make does not change them.
- **Copies your code makes** of what it reads from the pipe, as the pitfall above says.
- **Readers outside your code,** such as a debugger, a crash dump or the page file:
  [what it protects, and what it does not](/start/limits/).
:::

## Checklist

- Every `new Pipe(` and every `PipeReader.Create(` that carries a secret is given a pool of `SecureMemoryPool<byte>`.
- The pool is owned by the application, and disposed once, at shutdown.
- The minimum segment size is 4096 bytes or less.
- Both ends of the pipe are completed on every path.
- Nothing copies the pipe's bytes into an ordinary array.
- A read that an API wants as one span is read with `GetSpanLease(isSensitive: true)`, and the lease is disposed.
